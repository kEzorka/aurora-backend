## Порядок и зависимости

```
0.1 → 0.2 → 1.1 ─┬→ 1.8 → 1.3 → 1.4 ─→ 2.8 → 2.1 → 2.3 → 5.1 → 5.2 → 5.3
                  ├→ 1.2 (параллельно, для отладки без ключей)
                  └→ 1.10 (без него Aurora 1.5 нечем кормить)
2.1 → 2.2 → 3.1 → 3.2 → 3.3 → 5.5
0.3 → 4.8 → 4.7 → 4.1 → 4.2 → 4.3 → 4.4 → 4.5 → 6.1
```

Суммарно P0 ≈ **23 человеко-дня**, P0+P1 ≈ **37** (`ADDENDUM-01` добавил 1.8, 1.10,
2.8, 4.7, 4.8 в P0 и 1.9, 2.9, 5.8, 5.9 в P1).

Три предостережения по планированию:

1. **Начинать не с модели.** Соблазн запустить Aurora в первый день велик, но без адаптеров
   и хранилища её нечем кормить и некуда писать. Эпики 1–2 первичны; отлаживать конвейер
   на GFS, пока идёт возня с ключами.
2. **Задача 4.4 — не формальность.** GPU доступен только на время школы. Если не сохранить
   прогоны и их входы заранее, после школы демонстрировать будет нечего.
3. **2.8 идёт до 2.1, а не после.** Раскладка под два шага по времени — это форма
   хранилища, а не оптимизация: писать сначала «как получится», а потом добавлять часовой
   слой означает переписать всё уже записанное (`ADDENDUM-01`, шапка).
