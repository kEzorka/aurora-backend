# CODEX_CONTEXT.md — восстановленный контекст проекта

Дата аудита: **2026-08-03**. Код и тесты имеют приоритет над этим снимком.

## Назначение и стек

Проект — бэкенд прогноза погоды Aurora на глобальной сетке 0.25° и доступа к
истории ERA5 с 1940 года. Публичный P0-интерфейс — FastAPI JSON `/v1`; будущие
полосы — xpublish/Zarr и асинхронный экспорт.

Основной стек: Python 3.12, FastAPI, xarray, NumPy, Dask, Zarr v3 и SQLite.
Адаптеры работают с ECMWF Open Data, GFS, ARCO ERA5 и CDS. Инференсное окружение
с `microsoft-aurora` и CUDA отделено от сервисного. CI — GitHub Actions; Ruff,
mypy strict и pytest запускаются без сети и GPU. Развёртывание текущего дерева
в репозитории не описано Docker-, Compose-, systemd- или Terraform-файлами.

## Архитектура

`contracts/canon.py` задаёт каноническую сетку, поля, единицы и временные слои.
`adapters/` изолирует форматы источников и возвращает канонические Dataset.
`validators/` проверяет сообщения GRIB, структуру, семантику и физику до
публикации. `pipeline/` собирает входы и публикует прошедшие проверку данные.
`storage/` хранит прогноз в двух раскладках Zarr v3 и публикует его атомарно.
`cache/` проксирует историю по чанкам источника, хранит индекс и журнал в
SQLite, выполняет негативное кэширование и вытеснение. `api/` читает только
`storage`/`cache`, применяет публичные имена, единицы, лимиты и HTTP-кэширование.

Границы пакетов исполняются тестом `tests/test_boundaries.py`: API не знает об
адаптерах, конвейере и модели; адаптеры не знают о хранении и API; кэш может
знать об адаптерах, но не об API и модели.

## Текущее состояние

Закрыты канон и валидаторы, адаптеры GFS/ECMWF/ARCO/CDS, P0-хранилище, ядро
кэша и прогнозные JSON-эндпоинты с лимитами, единицами, ETag и метаданными.
Последняя завершённая часть BACKLOG 5.5 собирает историю из кэшированных чанков
и покрыта тестами `tests/cache/test_history.py`.

BACKLOG 5.5 завершён на ветке `codex/backend-continuation`: интегрированы
`/v1/history/point` и `/v1/history/grid`, холодный и тёплый пути, ошибки,
лимиты, агрегация, провенанс ERA5T и HTTP-кэширование доказаны тестами.

Реализация 2.5 добавлена после этого аудита: ленивое чтение ARCO, агрегация
полных финальных месяцев, атомарные раскладки `maps`/`series` и месячная карта
API готовы. Настоящий слой 1940–now в этой локальной сессии не строился, поэтому
критерий физического объёма 17 ГБ остаётся непроверенным.

Минимальный demo-клиент поставляется тем же FastAPI-приложением на `/` и
`/demo`. Он получает конкретное численное значение из point API и кодирует в
браузере GIF до 20 кадров из grid API, без CDN и отдельного Node build-контура.
`make demo` создаёт небольшой синтетический прогноз в штатном формате Zarr и
проходит тот же путь публикации/чтения, поэтому не подменяет backend mock-ответами.

Инференс модели ещё не начат, но устойчивая SQLite-очередь эпика 4.3 готова:
задача переживает рестарт через lease и `make forecast` больше не является
пустой точкой входа. Не начаты GPU-runner, приёмка (эпик 6), виртуальные чанки,
xpublish, VirtualiZarr/Icechunk и `earthkit-data` объявлены в service-профиле
и видны в `make setup`, но не интегрированы: пакетов нет в локальном venv,
а ночной профиль не разрешает сетевую установку или внешнюю приёмку. Экспорт
Zarr реализован отдельно и не зависит от этих пакетов.

## Предыдущий AI-контекст и рабочий процесс

`docs/HANDOFF.md` — подробный снимок прежней AI-assisted разработки и решений.
Репозиторий не содержит `CLAUDE.md`, `.claude/`, MCP-конфигурации, Cursor rules
или Copilot instructions; мигрировать команды, skills и hooks не требуется.
Совместимость сохраняется: существующие файлы не удаляются, `AGENTS.md`
добавляет только краткий путеводитель для Codex и других агентов.

Принятый процесс: одна ветка на задачу, Conventional Commits по-английски,
русские docstring/документы, зависимости источника и часы подставляются в
тестах, внешние пакеты импортируются лениво. Критерий завершения задаётся
`docs/BACKLOG.md`, доказательства фиксируются в `docs/PROGRESS.md`.

## Риски и технический долг

- Живые ECMWF, ARCO и CDS не проверялись автоматическими тестами; схемы и имена
  частично подтверждены только документацией поставщиков.
- Инференс, AuroraV1p5 и ключевые приёмочные метрики требуют недоступного локально
  CUDA-узла; старые GPU-замеры сохранены только как справка.
- `make setup` и `make forecast` теперь рабочие и покрыты тестами. `make
  ingest-*` всё ещё ссылается на отсутствующий orchestrator и остаётся
  ближайшим разрывом CLI.
- `README.md`, `SECURITY.md` и часть setup-документации содержат сведения об
  архивной реализации и местами расходятся с текущим деревом.
- API не имеет аутентификации и должен оставаться на loopback/доверенной сети.
- Месячная сеточная история включается после публикации `history/monthly`; без
  слоя `agg=monthly` для карты честно остаётся `400`.
- Процесс точной инвалидации ERA5T после выхода финального ERA5 не автоматизирован.
- Секреты и production-состояние нельзя выводить из репозитория; их требуется
  проверять отдельно и только чтением.
