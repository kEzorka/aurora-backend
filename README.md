# Weather Backend

Прогноз погоды на 10 суток моделью **Aurora** (0.25°, шаг 6 часов) и доступ
к историческим данным **ERA5** с 1940 года. Ответы — JSON; карты и гифки рисует
фронтенд.

Требования целиком — [`docs/README.md`](docs/README.md) и остальные документы
в `docs/`. Они источник истины: код обязан соответствовать им, а не наоборот.

## Состояние

Идёт переписывание с нуля. Что не так с предыдущей версией и что от неё
сохранено — [`docs/specs/2026-08-01-rewrite-design.md`](docs/specs/2026-08-01-rewrite-design.md).

Сделано:

| Модуль | Что в нём |
|---|---|
| `contracts/canon.py` | канон: оси, уровни, переменные, единицы, диапазоны — единственный источник истины о форме данных |
| `validators/` | четыре уровня проверок (`structure`, `semantics`, `physics`, `sanity`), `validation.json`, `make validate` |
| `tests/` | тесты без сети и без GPU, включая тест на направление зависимостей |

Дальше, в порядке выполнения: адаптеры GFS и ECMWF Open Data на настоящих
фикстурах, хранилище (Zarr v3, раскладки A и B, атомарная публикация), инференс
и архив прогонов, API `/v1`, кэш истории, метрики. Планы — в `docs/plans/`,
первый из них [`2026-08-01-01-foundation.md`](docs/plans/2026-08-01-01-foundation.md).

## Валидация

Валидатор ничего не чинит и ничего не публикует — он выносит вердикт. Отказ
обязан называть поле, полученное значение и ожидаемое: «validation failed» без
деталей на ревью не принимается (`docs/DATA_CONTRACT.md` §4).

```bash
make validate                                   # последний срез из artifacts/
python -m validators.cli path/to/forecast.zarr  # или конкретный
```

Код возврата — часть интерфейса: `1` значит «срез отвергнут», конвейер обязан
остановиться и оставить актуальным предыдущий срез.

## Разработка

```bash
make venv      # venv + минимальные зависимости разработки
make setup     # диагностика service-окружения без вывода секретов
make test      # pytest, без сети и без GPU
make lint      # ruff + mypy strict
```

Окружений два, и они не пересекаются: сервисное (без torch) и инференсное
(torch + CUDA). Списки — в `requirements/`, причина разделения — `docs/SETUP.md`.

## Что сохранено от предыдущей версии

- `bench/results/`, `bench/charts/`, `report/` — измерения, снятые на GPU
  до переписывания. Повторить их после школы будет негде, поэтому они лежат
  в репозитории намеренно и кодом не используются.
- [`docs/notes/previous-version-readme.md`](docs/notes/previous-version-readme.md) —
  прежний README. Его раздел «Things that are easy to get wrong here» стоил
  реального времени на V100: выбор чекпоинта, порядок уровней давления, сетка
  720 против 721 на выходе, единицы `lead_time`, `expandable_segments`. Всё это
  понадобится, когда дойдёт очередь до инференса.
- Ветка `archive/server-state` — код предыдущей версии целиком.
